# Client Management

Maintain client work so that records remain traceable, portable, and available on the locations the user has approved for that client.

## Establish the Client Context

1. Identify the client and the work being performed.
2. Reuse an S: drive path, OneDrive path, folder convention, or retention rule already provided in the current task or durable client instructions.
3. If no approved durable destination is known, ask the user for the applicable client S: drive and/or OneDrive location before creating, moving, or archiving client records. Do not guess from another client's paths.
4. Treat each client's storage topology as authoritative. Do not require every client to use the same folder names, root locations, or both storage systems.

## Preserve Working Records

For tracker, email-archive, or source-document work:

1. Keep derived records and their raw source material together in the approved durable location when the user requests ongoing continuity or cross-device access.
2. Preserve dated versions rather than overwriting the sole working copy. Use the client's established naming convention; if none exists, use an unambiguous ISO date or year/week convention.
3. Keep source provenance: record the source email, message, document, or system that supports a substantive tracker entry or derived record.
4. Keep temporary previews, generated decorative assets, and disposable staging files out of the durable client archive.
5. Before delivery, verify that the retained files open, the expected source material is present, and the saved location matches the approved client context.

## Safe File Handling

- Do not move, rename, delete, or replace client files without confirming the applicable client location and scope.
- Preserve existing client folder conventions and apply specialized filing skills when a task falls within their scope.
- Keep user-level skill-maintenance files, scratch work, and unrelated client data outside the client archive.
- When a requested archive structure conflicts with an existing client convention, surface the conflict and ask before changing the convention.

## Completion Check

Before closing a client-management task, confirm that the client context was known or obtained, durable records were saved only where approved, source provenance is recoverable, and no temporary or unrelated files were introduced into the client record.
